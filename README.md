# 런앤로컬 · 공익적 러닝 챌린지

**목표:** 전국 사용자의 현재 위치 또는 지정 출발지에서, 오늘 가능한 시간·거리·선호 환경에 맞는 코스를 찾고 신체활동을 지속하도록 돕는 공익적 러닝 챌린지입니다. 구매나 소비는 참여·완료의 필수 조건이 아닙니다. **현재 서울 성수·서울숲·뚝섬 실증권역과 기존 강릉시 전역을 지원하며, 전국 경로 지원은 개발 예정입니다.** 통계 기반 선호계수 학습과 건강 개선 효과 검증도 아직 완료되지 않았습니다.

실제 OpenStreetMap 보행망으로 계산하는 러닝 코스 추천 모바일 앱. Android·iOS 네이티브 프로젝트와 공개 체험 화면이 같은 추천 엔진과 화면을 사용합니다. 앱에는 코드와 지도 데이터가 포함되며 원격 웹페이지를 불러오는 설정을 사용하지 않습니다. 강릉시 행정구역 안의 OSM 보행 도로를 지원합니다. 정해진 예시 코스의 점수만 바꾸는 화면이 아니라, 입력한 출발점·목적지에서 경로를 생성합니다.

## 핸드폰 설치와 빌드

[Android APK 설치](https://run-and-local-gangneung.jason1207890.chatgpt.site/downloads/run-and-local.apk) · [공개 체험 화면](https://run-and-local-gangneung.jason1207890.chatgpt.site/). Android 7.0 이상을 지원하는 서명된 릴리스 APK이며 Google Play 등록판은 아닙니다. iOS Xcode 프로젝트는 `ios/App/App.xcodeproj`입니다. iPhone 실기기·App Store 배포에는 Apple 개발자 서명과 프로비저닝이 필요합니다.

`npm run sync:mobile`로 앱 코드를 빌드하고 두 플랫폼 프로젝트에 복사합니다. Android는 JDK 21·Android SDK 36에서 `cd android && ./gradlew assembleDebug`로 디버그 APK를 만들 수 있습니다. iOS는 Xcode에서 App 스킴을 빌드합니다. 배포용 서명 키·인증서는 포함하지 않으며, 릴리스 배포에는 본인의 서명 설정이 필요합니다.

## 실행

Node 24 권장. 이 폴더에서 `npm ci`, `npm run dev` 후 로컬 서버를 엽니다. `npm run lint`, `npm test`, `npm run build`로 검증합니다. 지도 데이터는 저장되어 있어 별도의 API 키가 필요 없습니다. 배경 지도 타일은 인터넷 연결이 필요합니다.

휴대폰 앱 화면만 브라우저에서 실행하려면 `npm run dev:mobile`, 정적 앱 빌드는 `npm run build:mobile`을 사용합니다. 이 경로는 Sites 배포 계정이 없어도 사용할 수 있습니다. `.openai/hosting.json`의 프로젝트 식별자는 기존 공개 체험 배포의 설정이며 인증정보가 아닙니다. GitHub 업로드만으로 기존 체험 앱이 자동 재배포되지는 않습니다.

이 저장소는 앱 소스·테스트·공개 지도 스냅샷을 포함합니다. 공모전 전체 분석 폴더, 국민조사 개인별 원자료, 개발자 환경설정, 서명 키와 빌드 산출물은 포함하지 않습니다. 아래 상위 `development/` 경로는 전체 작업공간의 자료 위치이며 이 앱 저장소에 들어 있는 파일은 아닙니다.

## 사용할 수 있는 기능

- 출발 거점 6곳, 지도 클릭, 선택적 현위치.
- 첫 진입: 이 기기에서 시작 → 러너 프로필 → 출발·목적지 → 오늘의 조건. 계정 인증 없이 기기에 저장합니다.
- 실제 카페·식당·공원·볼거리 검색, 목표 거리와 최대 거리, 페이스·총시간·체류 선택.
- 바다·강변·호수·흙길·도심 테마, 오르막·노면 선호, 계단·주요 도로·경사 미확인 구간 제외, 선택적 추정 경사 상한.
- 코스별 지표면 고도 그래프·추정 상승·경사·테마 포함률·노면 확인율 표시.
- 실제 보행 구간에 따른 편도·같은 길 왕복·다른 길 순환 계산. 최대 3개 후보와 추천 근거 비교.
- ‘크게 보기’에서 코스 전체 지도, ‘이 코스로 달리기’에서 지도와 타이머. 방향 화살표·출발/목적지·전체 코스/내 위치 버튼 제공.
- 현재 위치는 직접 켤 때만 표시합니다. 정확도·오래된 위치를 검사하며 지도 닫기·앱 백그라운드·일시정지 때 구독을 정리합니다. 위치 이력은 저장하지 않습니다.
- GPX 내보내기, 경로가 포함된 챌린지 계획 저장, 실제 거리·시간 직접 입력, 기록 JSON 내보내기.
- 기기 내부에 기록과 실행 중인 타이머 저장. 시작·일시정지·재개·종료를 지원합니다. 계정 간 동기화나 GPS 거리 자동 기록은 제공하지 않습니다.

처음에는 목적지가 비어 있어 사용자가 직접 선택합니다. 재방문에는 저장된 러너 프로필을 복원하고 오늘의 목적지부터 입력합니다. 재현용 기본 조건은 경포생태습지원 인근 → 강문해변, 목표 5km·최대 6km·60분·7분/km·체류 5분·바다·완만 선호·순환입니다.

## 검증과 한계

`tests/routing.ts`는 작은 시험 지도와 실제 지도 36조건의 연결·방향·목적지·형태·시간·거리·결측 처리를 검사합니다. `tests/records.ts`는 기록 파싱·손상자료·비정상 완주입력을 검사합니다. `tests/terrain.ts`는 실제 대안 경로·부호 있는 경사·결측·제외 조건·테마별 강릉 경로와 프로필 검사를 수행합니다. assertion 개수는 이용자 실험 수가 아닙니다. HTTP 응답·정적 검사·모바일/공개 화면 빌드를 확인했습니다. iOS Simulator에서 지도·설정·추천 흐름을 확인했으며, Android 실기기와 현장 보행 검증은 별도입니다. 타이머의 일시정지·재개·재실행·시계 역행·손상 데이터는 `tests/session.ts`로 검증합니다. `tests/navigation.ts`는 위치 유효성·시각·구간 거리·방향 화살표·이전 세션 호환·위치 권한/해제를 Node 내장 mock으로 검사합니다. 지도는 음성 턴바이턴·자동 재탐색·GPS 거리 기록·도착 판정을 제공하지 않습니다. 위치 오차와 현장 통행은 별도 확인이 필요합니다.

추천은 규칙 기반입니다. 새 입력은 목표 거리 30·지형 20·경사 15·노면 10·시간/풍경/편의/도로/조명 각 5의 기본 가중치를 사용합니다. 명시한 테마와 중복되는 이전 풍경 점수는 제외하며 정보 없는 항목의 가중치를 재분배합니다. 선택 테마 근거 구간 15% 이상인 혼합 코스만 추천합니다. 이 기준과 가중치는 설계 가정입니다. 경사 선호는 soft 조건이며 명시적 상한·제외 조건은 후보 탐색부터 적용합니다. 후보 간 경로 중복을 감점합니다. 시간 예산에는 체류·태그 기반 횡단 대기·도로 연결 간격과 달리기 10% 여유를 포함합니다. 최적해 보장·실측 소요시간·안전 검증·소비/건강 개선 효과를 의미하지 않습니다.

## 파일

- `app/run-app.tsx`: 입력·추천·기록 흐름.
- `app/run-setup.tsx`, `lib/profile.ts`: 첫 진입·러너 조건·기기 프로필.
- `app/route-terrain.tsx`: 지형 근거·고도 그래프.
- `app/map-view.tsx`: Leaflet 지도와 실제 경로.
- `app/navigation-screen.tsx`, `lib/navigation.ts`: 큰 지도·러닝 제어·위치/경로 표시.
- `lib/recommender.ts`: Dijkstra 탐색·후보 생성·하드 제약·순위.
- `lib/records.ts`: 기록 스키마 검사·완주 입력.
- `public/data/gangneung.json`: 강릉 전역 실제 지도·POI 스냅샷.
- `public/data/seongsu.json`: 성수·서울숲·뚝섬 실증권역 보행 도로망.
