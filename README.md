# 런앤로컬 · 강릉 러닝

실제 OpenStreetMap 보행망으로 계산하는 러닝 코스 추천 웹앱. 강릉 경포·초당·송정·안목 일부를 지원합니다. 정해진 예시 코스의 점수만 바꾸는 화면이 아니라, 입력한 출발점·목적지에서 경로를 생성합니다.

## 실행

Node 24 권장. 이 폴더에서 `npm ci`, `npm run dev` 후 로컬 서버를 엽니다. `npm run lint`, `npm test`, `npm run build`로 검증합니다. 지도 데이터는 저장되어 있어 별도의 API 키가 필요 없습니다. 배경 지도 타일은 인터넷 연결이 필요합니다.

## 사용할 수 있는 기능

- 출발 거점 6곳, 지도 클릭, 선택적 현위치.
- 실제 카페·식당·공원·볼거리 검색, 시간·페이스·최대거리·목적지 체류·풍경 선택.
- 실제 보행 구간에 따른 편도·같은 길 왕복·다른 길 순환 계산. 최대 3개 후보와 추천 근거 비교.
- GPX 내보내기, 경로가 포함된 챌린지 계획 저장, 실제 거리·시간 직접 입력, 기록 JSON 내보내기.
- 기기 브라우저에 기록 저장. 계정 간 동기화나 GPS 자동 완주 판정은 제공하지 않습니다.

기본 시연은 경포생태습지원 인근 → 강문해변, 45분·7분/km·체류 5분·최대 6km·물가·순환입니다. 다른 목적지나 시간을 선택하면 실제 경로를 새로 계산합니다.

## 검증과 한계

`tests/routing.ts`는 작은 시험 지도와 실제 지도 36조건의 연결·방향·목적지·형태·시간·거리·결측 처리를 검사합니다. `tests/records.ts`는 기록 파싱·손상자료·비정상 완주입력을 검사합니다. 합계 검사는 구간마다 수행되는 assertion이므로 11,660명을 실험했다는 뜻이 아닙니다. HTTP 응답·정적 검사·빌드를 확인했으며, 실제 브라우저 조작과 현장 보행 검증은 별도입니다.

초기 추천은 규칙 기반입니다. 시간 40%·풍경 35%·편의 15%·도로 10%를 기본으로 정보가 없는 항목의 가중치를 재분배합니다. 후보 간 경로 중복을 감점합니다. 시간 예산에는 체류·태그 기반 횡단 대기·도로 연결 간격과 달리기 10% 여유를 포함합니다. 최적해 보장·실측 소요시간·안전 검증·소비/건강 개선 효과를 의미하지 않습니다.

## 파일

- `app/run-app.tsx`: 입력·추천·기록 흐름.
- `app/map-view.tsx`: Leaflet 지도와 실제 경로.
- `lib/recommender.ts`: Dijkstra 탐색·후보 생성·하드 제약·순위.
- `lib/records.ts`: 기록 스키마 검사·완주 입력.
- `public/data/gangneung.json`: 실제 지도·POI 스냅샷.

배포 주소와 최종 검토 결과는 상위 `development/개발현황.md`에 기록합니다.
